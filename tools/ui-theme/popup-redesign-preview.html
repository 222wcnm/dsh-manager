popup 排版优化 · 方案预览（对照 + 4 版）

现状问题：popup 是自上而下线性堆叠——应用栏 → 状态卡 → 会话区（默认展开）→ 操作区 → 底栏， 再往后所有新信息（M9 会话、M10 颜色角色、将来的深链/统计…）都只能再加一层，popup 只会越来越长； Chrome popup 高度上限约 600px，超出的部分变成页内滚动，体验断崖。 各版本的共同思路是 把「纵向堆叠」改为「横向分组 / 视图切换 / 覆盖层」，让高度有上限。 版本卡下的 ✓/△/✗ 标注为 ui-ux-pro-max 规则库审计结果（符合 / 部分 / 违反）。 点各版本顶部的状态按钮可以切换预览；高度数字为实测渲染高度。

版本核心思路默认高度会话长列表代价 / 偏好 V0 现状线性堆叠，设置内联追加—直接撑高 body，50 条即超限无改动；问题延续（✗ 无主 CTA · ✗ 设置全铺） V1 标签分视图概览 / 会话 / 设置三页签—页内滚动，不再撑高概览多一次点击；沿用 dsh web 分页习惯（✓ 披露 · ✓ 激活态 · △ 无主 CTA） V2 合并头 + 抽屉状态并入顶栏；会话折叠为计数条—点计数条开抽屉（限高滚动）状态细节少一行；抽屉多一次点击（✓ 披露 · ✓ chip 触达 · △ 无主 CTA） V3 双栏 360px左状态+操作，右会话；横向换纵向—右侧列内滚动popup 加宽到 360；窄栏标题省略更多（✓ 形态契合 · ✓ 披露 · △ 无主 CTA） V4 命令式主操作即状态（打开 Web UI 大按钮）—抽屉展开；计数条仅摘要三个次要操作退化为图标+短字；状态简化为按钮内一行（✓ 唯一主 CTA · ✓ 披露 · ✓ SVG 图标 · ✓ 触达）
